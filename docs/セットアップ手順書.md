## 概要

11月24日(火)中にこの手順を終えれば、12月26日(土)まで5分おきに待ち時間が自動で貯まり、いつでもPCで分析できます。作業は約30分、費用は0円です。

- **集める**:GitHub Actionsが、パークの営業中(現地7時〜24時ごろ)に5分おきにQueue-Timesから両パークの待ち時間を取得し、CSVに追記します。PCを閉じていても動きます
- **まとめる**:PCで `warehouse.py` を実行すると、CSVが分析用のデータベース(DuckDB+Parquet)になります
- **分析する**:`analysis.ipynb`(Jupyter)、`model.py`、`insights.py`、`plan.py` で分析・予測・ルート計算をします

**必要なもの**

| もの | 用途 | 備考 |
| --- | --- | --- |
| GitHubアカウント | データ集め(公開リポジトリ) | 無料 |
| PC(Mac/Windows) | 分析 | Python 3.10以上 |
| disney-waits.zip | 一式 | チャットで受け取ったもの |

日付の注意:GitHub上の時刻はUTC、データは現地(太平洋時間)、日本時間とは17時間差です。現地の12月1日の営業は、日本時間の12月2日0時〜17時ごろにあたります。

## Claude Codeで進める場合(手順1〜3をまとめて任せる)

手順1〜3はClaude Codeに任せられます。ブラウザでの手作業がほぼなくなり、トークンやAPIキーを手で渡す必要もありません。待ち時間の取得元(Queue-Times)はキー不要です。

**事前準備(初回だけ・約10分)**

1. Claude Codeを入れ、Claudeのアカウントでログインする(サブスクリプションで使えるので、AnthropicのAPIキーは不要)
2. ターミナルで `gh --version` と `git --version` を実行する。どちらかが出なければ、Claude Codeに「ghとgitが入ってなければ入れて」と頼む
3. `gh auth login` を実行し、GitHub.com → HTTPS → ブラウザでログイン、の順に進める。これでClaude CodeがGitHubを操作できるようになる
4. disney-waits.zip を展開し、そのフォルダでClaude Codeを起動する

**Claude Codeへの頼み方(このまま貼ってよい)**

```text
このフォルダをGitHubに公開リポジトリ disney-waits として作ってpushして。
.github/workflows/collect.yml も含めること。
リポジトリのActionsのWorkflow permissionsを「Read and write」にして、
collect-wait-times を手動実行し、成功したか確認して。
終わったら、Pythonの環境を確認して pip install -r requirements.txt まで実行して。
```

**終わったら自分で確認すること**

- GitHubのリポジトリに `.github/workflows/collect.yml` がある
- Settings → Actions → General の「Workflow permissions」が Read and write になっている。Claude Codeが変更できなかったときは、ここだけ手で切り替える
- Actionsタブの実行結果が緑のチェック。閉園中は `park closed, skip` と出れば正常(下の「結果の見方」を参照)

トークンを使う場合は、Fine-grained tokenで対象をこのリポジトリだけに絞る(Contents・Actions・Administration を Read and write)。チャットやファイルには貼らない。

この節をやった場合は、手順1〜3は飛ばして手順4へ進みます。

## 手順1:公開リポジトリを作ってアップロードする(約10分)

1. disney-waits.zip をPCで展開する。中に `.github` という隠しフォルダがあることを確認する(MacはFinderで Command+Shift+. 、Windowsは「表示 → 隠しファイル」)
2. GitHubにログインし、右上の「+」→「New repository」
3. Repository name に `disney-waits`、**Public** を選び、他は何もチェックしないで「Create repository」
4. できたページの「uploading an existing file」を押し、展開したフォルダの**中身を全部**ドラッグ&ドロップして「Commit changes」
5. リポジトリのトップに `.github/workflows/collect.yml` があるか確認する

ドラッグ&ドロップで `.github` が入らない場合は、「Add file → Create new file」でファイル名に `.github/workflows/collect.yml` と打ち、zip内の同名ファイルの中身を貼り付けて保存します。

## 手順2:書き込み権限を設定して動作確認する(約10分)

1. リポジトリの「Settings」→ 左の「Actions」→「General」
2. 下の方の「Workflow permissions」で **Read and write permissions** を選んで「Save」
3. 上の「Actions」タブを開き、「I understand my workflows, go ahead and enable them」が出たら押す
4. 左の「collect-wait-times」→ 右の「Run workflow」→ 緑の「Run workflow」
5. 1〜2分待ち、実行結果が緑のチェックになれば成功

**結果の見方**

| 表示 | 意味 | すること |
| --- | --- | --- |
| 緑チェック+ `data/DL/日付.csv` ができた | 成功 | そのまま放置 |
| 緑チェックでログに `park closed, skip` | 現地が閉園中 | 現地の営業時間(日本時間でおよそ0時〜17時)にもう一度実行 |
| 赤のXで `Permission denied` / `403` | 書き込み権限がない | 手順2-2をやり直す |
| 赤のXで `fetch failed` | データ元につながらない | 時間を置いて再実行。続くならログをClaudeに貼る |

定期実行はここから自動で始まります。最初の定期実行は、設定から数十分遅れることがあります。

## 手順3:PC側の準備(約10分、初回だけ)

1. **Pythonを入れる**:ターミナル(Windowsは「ターミナル」またはPowerShell)で `python3 --version`(Windowsは `python --version`)を実行。3.10以上が出ればOK。なければ python.org から入れる(Windowsは「Add python.exe to PATH」にチェック)
2. **リポジトリをPCに持ってくる**:一度だけ次を実行(`<ユーザー名>` は自分のGitHub名)

```bash
git clone https://github.com/<ユーザー名>/disney-waits.git
cd disney-waits
```

3. **分析の道具を入れる**

```bash
pip install -r requirements.txt
```

Windowsの場合は、続けて `pip install tzdata` も実行します。`git` がないと言われたら、Macは表示される案内に従って入れる、Windowsは git-scm.com から入れます。

## 手順4:分析を実行する

分析のたびに、`disney-waits` フォルダで次を上から順に実行します。最初の `git pull` で最新のデータが手元に入ります。

```bash
git pull
python warehouse.py
python model.py --park DL
python insights.py --park DL
jupyter lab analysis.ipynb
```

| コマンド | 必要なデータ | 出力 | 中身 |
| --- | --- | --- | --- |
| `python warehouse.py` | 1日分〜 | `warehouse/` | 分析用データベース(DuckDB+Parquet) |
| `python analyze.py --park DL` | 1日分〜 | `profiles/` | 15分ごとの待ち時間、空く時間帯・混む時間帯 |
| `python model.py --park DL` | 3日分〜 | `models/` | 混雑指数、待ち時間予測モデル、ゲスト占有率、レポート |
| `python model.py --park DL --backtest` | 5日分〜 | `models/DL_backtest.csv` | 待ち時間予測の精度(平均誤差) |
| `python insights.py --park DL` | 5日分〜 | `insights/` | グループ分け、朝いちばんの価値、シス調 |
| `python plan.py plan_DL.json` | 1日分〜 | `plan_DL.md` | 1日の最適な回り方 |
| `jupyter lab analysis.ipynb` | `warehouse.py` の後 | ブラウザ | SQLで自由に分析 |

カリフォルニア・アドベンチャーは `--park DCA`、`plan_DCA.json` に置き換えます。レポート(`models/DL_report.html`、`insights/DL_report.html`)はファイルをダブルクリックするとブラウザで開きます。

## 日々の運用とトラブル対応

運用中にやることは、1日に1回データが増えているかを見るだけです。

- [ ] 毎朝(日本時間):GitHubの `data/DL/` と `data/DCA/` に、現地の前日分のCSVがあるか見る
- [ ] 週に1回:「Actions」タブに赤のXが続いていないか見る
- [ ] 気づいたとき:`calendar_extra.csv` にイベント・天気・公式の営業時間を書き足す。`shows.csv` の時刻を公式アプリに合わせる

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| 実行が10〜15分おきになっている | GitHubの混雑で定期実行が遅れる | 仕様。分析は15分単位なので影響なし |
| 実行は緑だがCSVが増えない | 現地が閉園中、またはデータの更新がまだ | 営業中なら数回後に増える |
| 赤のXが何回も続く | データ元の障害、または仕様変更 | ログをClaudeに貼る |
| `git pull` で失敗する | 手元のファイルを書き換えた | 手元の `data/` は編集しない。`git stash` してからもう一度 |
| 分析で「データがありません」 | `git pull` を忘れた | `git pull` してから実行 |
| グラフの日本語が□になる | 日本語フォントがない | Mac/Windows標準なら自動で選ばれる。それ以外は Noto Sans JP を入れる |

12月26日で分析を終えたら、「Settings → Actions → General」で「Disable actions」にするか、`collect-wait-times` を「Disable workflow」にして止めます。データはそのまま残ります。
